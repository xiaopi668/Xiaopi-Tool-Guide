# 远程开发：在本机编辑服务器上的代码

> 代码在远端跑，界面在本机，改完不用再 scp

`VS Code` · 建议 15 分钟 · 进阶

## 学完这一节，你会

- 说清 Remote - SSH 是怎么工作的
- 配好 ssh 别名并连上远端
- 会用端口转发看远端服务
- 连不上时能从日志里找到原因

## Remote - SSH 到底在做什么

装上 Remote - SSH 之后，VS Code 仍然是本机那个窗口，但它会在远端机器上拉起一个 VS Code Server。文件读写、语言服务、终端、调试全部在远端执行，界面通过 SSH 隧道传回本地。

结果是你用本机的主题、字体、快捷键，编辑的是服务器上的文件，⌘S 即生效，不用再 scp、不用再 rsync、也不用在 vim 里和缩进较劲。

## 连上第一台机器

### 1. 装 Remote - SSH

扩展面板搜 Remote - SSH（发布者是 Microsoft），装上。它会连带装上编辑 SSH 配置文件的那个小插件。

### 2. 从命令面板发起连接

⌘⇧P 输入 `Remote-SSH: Connect to Host`，选你配好的别名；还没有别名就选 Add New SSH Host，填 user@host。

### 3. 等远端 server 装好

第一次连接会在远端下载 VS Code Server，状态栏显示 Setting up SSH Host 加主机名。公司网络访问不了下载地址时，这一步会卡很久，最后报 Downloading VS Code Server failed。

### 4. 打开远端目录

连上后左下角显示 SSH: 你的主机名，再用 File → Open Folder 打开远端路径。此时资源管理器里的文件全部在服务器上。

## ~/.ssh/config 配一个别名

```text
Host myserver
    HostName 203.0.113.10
    User deploy
    Port 2222
    IdentityFile ~/.ssh/id_ed25519
    ServerAliveInterval 30
    ServerAliveCountMax 3
```

> 写完记得 chmod 600 ~/.ssh/config，权限太宽 ssh 会直接忽略它并报 Bad owner or permissions。之后 ssh myserver 和 VS Code 里选 myserver 用的是同一份配置。ServerAliveInterval 30 表示每 30 秒发一次心跳，防止 NAT 把空闲连接掐掉。

## 先在终端里确认 ssh 本身能通

```bash
$ ssh myserver
Welcome to Ubuntu 22.04.4 LTS (GNU/Linux 5.15.0-105-generic x86_64)

 * Documentation:  https://help.ubuntu.com
Last login: Thu Nov 20 21:03:11 2025 from 198.51.100.7
deploy@ubuntu-2gb:~$
```

> VS Code 用的就是这条命令背后的 ssh。这里能进，Remote-SSH 才能连；这里就卡住，先解决密钥、端口和跳板机，别在编辑器里瞎试。

## 从命令行直接开远端目录

```bash
$ code --remote ssh-remote+myserver /srv/app
```

> 在你本机的终端执行：用远程模式打开 /srv/app，这个路径是远端路径，不是本机路径。第一次仍然要等远端 server 下载完；路径写错会打开一个空目录，而不是报错。

## 连接之后，东西在哪一端

| 东西 | 在哪 | 含义 |
| --- | --- | --- |
| 文件树、搜索、Git | 远端 | 打开的是远端路径，本机没有自动副本 |
| 集成终端 | 远端 | 命令在服务器上执行，改的是服务器上的文件 |
| 语言服务、ESLint、调试器 | 远端 | 第一次会提示 Install in SSH，要在远端再装一次 |
| 主题、字体、快捷键 | 本机 | UI 类插件不需要在远端重装 |
| 端口转发 | 两端之间 | 远端 3000 映射成本机的 localhost:3000 |

## 端口转发：用本机浏览器看远端服务

远端跑着 `npm run dev`，你在本机浏览器打开 localhost:3000 却是空白——那个端口在本机上根本没人监听。解决办法是端口转发（port forwarding）：在面板（Ports）里点 Forward a Port 填 3000，或者从命令面板执行 `Ports: Focus on Ports View`。

终端输出里出现 http://localhost:3000 时，VS Code 一般会自动识别并转发，右下角弹一个提示。转发借 SSH 隧道走，默认只有本机能访问，不会把端口暴露到公网。

## 三种远程方式怎么选

| 方式 | 什么时候用 | 代价 |
| --- | --- | --- |
| Remote - SSH | 代码本来就在服务器或云主机上 | 要有 SSH 权限，网络差时输入延迟明显 |
| Dev Containers | 想让每个项目有独立依赖环境，比如不同 Node 版本 | 要装 Docker，镜像占磁盘和内存 |
| WSL | 你在 Windows 上开发，但项目依赖 Linux 工具链 | 文件放 /mnt/c 下读写很慢，要放到 WSL 自己的文件系统里 |

> **注意：连不上的时候先看这几条**
>
> `Could not establish connection to "myserver": Permission denied (publickey).` 密钥没被加载。检查 IdentityFile 指向的文件是否存在，或者先 `ssh-add ~/.ssh/id_ed25519`。
>
> `Could not establish connection to "myserver": Timed out while waiting for handshake` 是网络层就不通，端口、安全组、跳板机逐个排。
>
> 远端磁盘满也会表现为连不上：登录远端执行 `df -h` 看根分区用了多少。清理时注意 `rm -rf ~/.vscode-server` 会删掉远端的语言服务和装过的远端插件，下次连接要重新下载，正在用这台机器的人会当场断线。

> **提示：断开与重连**
>
> 直接关窗口，远端的 server 不会立刻退出，过一段时间才被回收；想马上释放，用命令面板的 `Remote-SSH: Kill VS Code Server on Host`。重连同一台机器时，未保存的编辑器内容通常还在，因为热退出（hot exit）把状态存在了远端。
>
> 网络断了不用重走整个流程，编辑器会自动重连；实在连不上，执行 `Remote: Close Remote Connection` 回到本地，再连一次就好。

## 动手练一练

没有服务器也能练：用 localhost 或一台你能登录的机器，把下面的流程走完。

1. 在 ~/.ssh/config 里给一台机器加别名，用别名登录一次 —— `ssh myserver`
2. 在 VS Code 里 Connect to Host，打开远端的一个目录
3. 在远端终端执行 node -v，确认命令跑在服务器上 —— `node -v`
4. 把远端的 3000 端口转发到本机，用浏览器打开验证

**完成标准**：左下角显示 SSH: 主机名，终端 pwd 出来是远端路径，就算走通了。

## 小测验

<details>
<summary>展开题目与答案（3 题）</summary>

**1. Remote - SSH 连上之后，文件实际存在哪里？**

- A. 本机缓存了一份完整副本
- B. 远端机器上
- C. VS Code 的安装目录里
- D. 浏览器的存储里

<details><summary>答案</summary>

**B**。编辑器只是界面，读写都通过 SSH 在远端完成，本地没有自动副本。这也是断网之后文件打不开、搜索失效的原因。

</details>

**2. 远端跑着 dev server，本机浏览器打开 localhost:3000 是空白，怎么办？**

- A. 把服务改成 80 端口
- B. 在 Ports 面板里把 3000 转发出来
- C. 重装 Remote - SSH
- D. 在远端执行 curl 本机地址

<details><summary>答案</summary>

**B**。这个端口在本机上没人监听，需要用端口转发把远端 3000 通过 SSH 隧道映射到本机，然后再访问 localhost:3000。

</details>

**3. 远端 .vscode-server 占满磁盘，删之前要注意什么？**

- A. 随便删，删了没有影响
- B. 删掉后远端插件和语言服务要重新下载，别人会断线
- C. 必须先重启服务器
- D. 必须改掉 ssh 端口

<details><summary>答案</summary>

**B**。整个目录是远端 server 的家，删掉等于把远端开发环境重置。正在用这台机器的人会立刻断线，下次连接要等重新下载。

</details>
