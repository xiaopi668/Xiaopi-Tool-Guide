# 插件：少而精

> 装之前花两分钟判断，比装完再排查省事

`VS Code` · 建议 14 分钟 · 基础

## 学完这一节，你会

- 用三个问题筛掉不靠谱的插件
- 知道每个常用插件解决什么问题
- 会用 command line 装、列、卸插件
- 遇到冲突时能定位到具体插件

## 插件改的是编辑器本身

插件（Extension）不是皮肤，它能读你打开的所有文件、能执行命令、能联网、能在保存时改写内容。所有插件都跑在同一个扩展宿主（Extension Host）进程里，一个插件卡住，整个窗口的补全、跳转、格式化都会跟着停。

所以装之前先花两分钟判断三件事：它还在维护吗，值不值得为它付启动时间，它要的能力配得上它干的事吗。

## 装之前先问三个问题

### 1. 还在维护吗

详情页看 Last updated 和安装量，再去 GitHub 看最近一次提交。一年没更新、issue 区没人回的插件，遇上新版编辑器出问题只能你自己扛。

### 2. 会不会拖慢启动

命令面板执行 `Developer: Show Running Extensions`，能看到每个插件的激活耗时（activation time）。几十毫秒无所谓，超过一秒的通常是启动时要扫全目录的插件。

### 3. 权限合理吗

详情页会标它跑在哪一端（UI 还是 Workspace），以及是否要求工作区受信任（Workspace Trust）。配色插件不该读文件，代码片段插件不该联网。

## 推荐清单：九个常用的

| 插件 | 解决什么 | 什么时候别装 |
| --- | --- | --- |
| Chinese (Simplified) Language Pack | 把菜单和设置界面换成中文 | 你已经习惯英文，装了反而对不上教程里的命令名 |
| Error Lens | 把错误信息直接印在行尾 | 文件很大、报错很多时，行尾文字会把代码挤到看不见 |
| Prettier - Code formatter | 统一 JS、TS、CSS、Markdown 的格式 | 项目已经用 ESLint 的排版规则，两套规则会互相改回去 |
| ESLint | 把 ESLint 的问题显示成波浪线 | 项目里没有 eslint 依赖和配置文件，它只会报找不到配置 |
| GitLens | 看每一行的提交人和提交时间 | 大仓库里全文件开 blame 标注会明显变慢 |
| Live Server | 起本地静态服务器，保存后自动刷新 | 项目自己有 dev server（Vite、Next）时，两个服务器抢端口 |
| Path Intellisense | 补全 import 里的文件路径 | TypeScript 项目自带路径补全，装了会有两份候选 |
| Code Spell Checker | 拼错的英文单词画波浪线 | 代码里全是拼音缩写和业务名词时，误报会盖住真正的错 |
| Material Icon Theme | 给文件树加图标，扫一眼分辨类型 | 纯黑极简风格下，彩色图标会显得很花 |

## 用命令行装一个、列出已装的

```bash
$ code --install-extension esbenp.prettier-vscode
Installing extensions...
Installing extension 'esbenp.prettier-vscode'...
Extension 'esbenp.prettier-vscode' was successfully installed.
```

> 在哪个目录执行都行，装完要重开窗口才生效。卸载是 code --uninstall-extension 加同一个 id；id 不是插件显示名，用 code --list-extensions 能看到真实 id，排查「到底装了什么」时最有用。

## .vscode/extensions.json 写推荐清单

```json
{
  "recommendations": [
    "dbaeumer.vscode-eslint",
    "esbenp.prettier-vscode",
    "usernamehw.errorlens",
    "streetsidesoftware.code-spell-checker"
  ],
  "unwantedRecommendations": [
    "hookyqr.beautify"
  ]
}
```

> 推荐列表不会自动安装，只会在同事打开项目时弹一个提示。unwantedRecommendations 用来挡掉和团队格式化规则冲突的插件，比如早已停更的 Beautify。

> **注意：插件冲突：一次保存被改了两次**
>
> 典型症状：按 ⌘S 时缩进先变成一种样子，又跳回另一种；或者右下角出现两个格式化器抢活。常见原因是 Prettier 和 ESLint 都开了保存时格式化。
>
> 排查顺序：在 `.vscode/settings.json` 里把 `editor.defaultFormatter` 写死成一个；再看 ESLint 的 `eslint.format.enable` 是不是也开着；还不行就执行 `Extensions: Disable All Installed Extensions`，然后一半一半地开回来，两三轮就能定位。
>
> 状态栏出现 `Extension host terminated unexpectedly` 时，打开命令面板的 `Developer: Open Extension Logs Folder`，报错在时间最近的那个目录里。

> **提示：按工作区禁用，而不是卸载**
>
> 插件详情页的齿轮菜单里有 Disable (Workspace)：只在这个项目里关掉，换个项目照常启用。它比卸载安全，也不用担心以后忘了装回来。排查问题时先用它，确认是哪个插件惹的祸，再决定要不要真的卸掉。

## 两种装法

| 见一个装一个 | 按需装加工作区推荐 |
| --- | --- |
| 装了三十多个插件 | 只留格式化、Lint、Git 三个刚需 |
| 打开项目时扩展宿主启动要两三秒 | extensions.json 写推荐，同事第一次打开会收到提示 |
| 同事格式化出来的结果和你不一样 | 冲突插件写进 unwantedRecommendations |
| 出问题不知道是哪个插件 | 出问题用 Disable (Workspace) 二分排查 |

> 插件是长期成本：每次启动都要加载，每次升级编辑器都要重新验证。留十个你天天用的，比装五十个偶尔用的划算得多。

## 启动慢先看谁在拖

命令行执行 `code --status`，会打印当前窗口、进程、以及每个插件的加载耗时和内存占用。启动明显变慢时先跑这个，比一个个禁用插件去猜快得多。

另外 `code --disable-extensions` 能开一个完全不加载插件的窗口，用来确认问题到底出在插件还是编辑器本身。

## 什么时候该禁用，什么时候该卸载

临时排查、只在某个项目里不需要的，禁用；一年都没启用过、或者已经被官方功能替代的，卸载。卸载前记一下 id（`code --list-extensions`），以后要装回来直接 `code --install-extension` 跟上 id，不用再去搜索框里翻。

## 动手练一练

打开扩展面板，把装过的插件过一遍，再给一个真实项目写推荐清单。

1. 用 code --list-extensions 列出你现在装的所有插件 —— `code --list-extensions`
2. 在扩展面板里按 Last Updated 排序，挑出一年没更新的
3. 给一个真实项目写 .vscode/extensions.json 推荐清单
4. 对其中一个插件试一次 Disable (Workspace)，再用 code --status 看启动耗时

**完成标准**：你能说清留下的每个插件解决了什么问题，其余已经禁用或卸载。

## 小测验

<details>
<summary>展开题目与答案（3 题）</summary>

**1. 判断一个插件还值不值得用，最先看什么？**

- A. 图标好不好看
- B. 最近一次更新时间和 issue 有没有人回
- C. 安装量是不是第一
- D. 是不是官方出的插件

<details><summary>答案</summary>

**B**。更新停了一年、issue 没人处理，遇上新版本编辑器的兼容问题只能自己扛。安装量高不代表现在还在维护，这两个指标要一起看。

</details>

**2. 同事拉下项目后格式化结果和你不一样，最该做什么？**

- A. 让他自己装一个 Prettier
- B. 把格式化设置和推荐插件写进工作区与 extensions.json
- C. 每次提交前手动整理一遍
- D. 关掉保存时自动格式化

<details><summary>答案</summary>

**B**。把 editor.defaultFormatter 和推荐插件写进仓库，工具链就跟着代码走；只靠口头交代，换个人、换台机器就会漂。

</details>

**3. 想让某个插件只在这个项目里关闭，用哪个操作？**

- A. 把它卸载掉
- B. 在详情页选 Disable (Workspace)
- C. 删掉 .vscode 目录
- D. 关掉扩展面板

<details><summary>答案</summary>

**B**。Disable (Workspace) 只影响当前工作区，其他项目照旧启用，适合排查冲突；卸载是全局的，下次要用还得重新装回来。

</details>

</details>
