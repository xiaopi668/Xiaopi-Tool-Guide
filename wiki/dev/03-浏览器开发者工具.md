# 浏览器开发者工具

> 看清页面在发什么请求、报什么错，不用靠猜

`开发环境与工具链` · 建议 15 分钟 · 基础

## 学完这一节，你会

- 会用两个平台各自的键打开面板
- 在 Elements 里改样式并看懂盒模型
- 用 Console 顺着报错找到自己那一行
- 用 Network 查一次接口的完整往返

## 它是什么，怎么打开

开发者工具（DevTools）是浏览器内置的一套面板：看页面结构、样式、网络请求、控制台报错、本地存储。它**不会改动线上页面**，所有修改只存在于你自己的浏览器里，刷新就还原。

macOS 用 `⌥⌘I`，Windows 用 `F12` 或 `Ctrl+Shift+I`。面板默认停在右侧或下方，拖它的标题栏可以换位置，点右上角三个点是更多面板的入口。

## Elements：看结构，也看盒模型

左上角那个箭头图标（或 `⌥⌘C`）点亮后，鼠标悬停到页面上，对应节点会高亮。点一下，右侧 Styles 面板列出这个元素命中的全部 CSS 规则，**被划掉的行表示被更具体的选择器覆盖了**——样式不生效时先看这里有没有划掉。

双击属性值可以当场改，比如把 color 改成红色，页面立刻变。往下滚到底部是盒模型（box model）图：由内到外是 content、padding、border、margin，鼠标移到某一层，页面上对应区域会亮。**元素为什么比你想的宽？九成是 padding 或 margin，不是 width。**

## Console：报错的第一现场

红字就是错误，点开左侧三角能看到调用栈（stack trace）。看**最上面一排属于你项目的那个文件**，例如 `app.js:42`，点它直接跳到 Sources 对应行。

输入框可以执行任意 JavaScript，作用在当前页面，刷新就没了。`$0` 指向你刚才在 Elements 选中的元素，所以 `$0.style.background = "red"` 能直接改它的底色；`copy($0.outerHTML)` 把它的 HTML 复制进剪贴板。

## Console 里最常用的五行

```bash
console.log("用户数据", user)      // 普通输出，可以跟多个参数
console.warn("旧接口即将下线")       // 黄色警告
console.error("请求失败", err)       // 红色，带调用栈
console.table(list)                 // 数组或对象打成表格，比 log 好读
console.time("render"); /* 代码 */; console.timeEnd("render")   // 测一段代码耗时
```

> 上线前把调试用的输出清掉，尤其是打印 token、手机号、完整接口返回的那几条。这些内容在用户浏览器里是明文可见的。

## Network：一次请求的完整证据

打开 Network 面板再刷新页面，每条请求都会列出来。信息太多就先点 **Fetch/XHR**，只看接口。点开一条，右侧分四块：Headers 看状态码和请求头，Payload 看你发出去的参数，Response 看服务端返回的原文，Timing 看每一段耗时。

两个开关能省很多时间：**Disable cache** 勾上后请求不走缓存，改完代码立刻看到新版本；顶部限速选 **Slow 3G**，能复现弱网下的样子——加载慢、按钮点了没反应这类问题基本只能这样查。

## 最该看懂的几个状态码

| 状态码 | 含义 | 接下来查什么 |
| --- | --- | --- |
| 200 | 成功 | 看 Response 里的数据对不对，不要只看页面显示 |
| 301 / 302 | 重定向 | 请求地址写错了，或者 http 被跳到了 https |
| 304 | 走了缓存，没有重新下载 | 要拿最新内容就勾 Disable cache 再刷新 |
| 401 / 403 | 没登录 / 登录了但没权限 | 看请求头里有没有带上 Cookie 或 Authorization |
| 404 | 路径不存在 | 对比接口文档，注意结尾斜杠和大小写 |
| 500 | 服务端崩了 | 不是前端问题，把这条请求和返回贴给后端 |

## Sources：让代码停在你要看的那一行

在 Sources 里找到你的 JS 文件，点行号就设了一个断点（breakpoint）。代码跑到这行会暂停，右侧能看到此刻所有变量的值，鼠标悬在变量上也行。上方按钮依次是继续、单步跳过、单步进入、跳出。

临时调试更快的办法是在代码里写一行 `debugger`：只要 DevTools 开着就会停在那里，关掉面板就不影响线上用户。

## Application：前端到底存了什么

Application 面板能看到 Local Storage、Session Storage、Cookie、Cache Storage。查登录状态最常看 Cookie：`HttpOnly` 打了勾的 Cookie 是 JavaScript 读不到的，所以 `document.cookie` 里看不见它**不代表它不存在**。

改一个值再刷新，就能验证这个字段到底影不影响页面。清站点数据也在这一页：左下 Clear storage，勾上要清的项，点 Clear site data。

> **提示：勾上 Preserve log，别让日志被跳转冲掉**
>
> 登录、支付这类流程提交后会跳转页面，而 Network 和 Console 默认在跳转时清空——你正要看的那个失败请求就这么没了。在 Network 顶部勾 **Preserve log**，Console 的右上角设置里也有同名项。
>
> 查「点提交之后报 500」这类问题，这一项是第一个要勾的。也可以在命令菜单里把限速调成 Offline，模拟断网看页面怎么兜底。

## 动手练一练

随便打开一个网站，用开发者工具找出它发出的一个接口请求，再用控制台改一个元素的样式。

1. 打开任意页面，打开面板并切到 Network，刷新一次 —— `location.reload()`
2. 点 Fetch/XHR 筛选，点开一条请求，在 Response 里找到返回的 JSON
3. 切到 Console，用 $0 给选中元素加一层描边 —— `$0.style.outline = "2px solid red"`
4. 勾上 Disable cache 再刷新，看同一条请求的体积有没有变小

**完成标准**：你能说出这条请求的状态码、返回里有哪些字段，也看到 $0 改的是哪个元素。

## 小测验

<details>
<summary>展开题目与答案（3 题）</summary>

**1. 在 Elements 里改完 CSS，刷新页面就还原了，为什么？**

- A. 浏览器有 bug
- B. 面板里的修改只存在当前页面，不会写回源文件
- C. 缓存没清
- D. 必须先保存工作区

<details><summary>答案</summary>

**B**。Elements 的修改只作用于当前页面的内存，刷新即丢弃。要永久生效必须改源文件，或者用 Workspace 把面板和本地目录关联起来。

</details>

**2. Network 里一条请求显示 304，说明什么？**

- A. 请求失败了
- B. 服务端出错了
- C. 浏览器用了缓存，内容没变，没有重新下载
- D. 被重定向到了别的地址

<details><summary>答案</summary>

**C**。304 Not Modified 是协商缓存的结果：浏览器带上 If-None-Match 问服务端，服务端说没变，于是省掉一次下载。想强制拿新内容就勾 Disable cache。

</details>

**3. 调试登录跳转时请求记录消失了，应该怎么做？**

- A. 重新登录一次
- B. 在 Network 里勾上 Preserve log
- C. 先清空浏览器缓存
- D. 换一个浏览器再试

<details><summary>答案</summary>

**B**。页面跳转时 Network 和 Console 默认清空记录。勾上 Preserve log 后，跳转前的请求和报错都会留下来，正好用来查提交之后发生了什么。

</details>

</details>
