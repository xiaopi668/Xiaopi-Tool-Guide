# dsh：DeepSeek Harness

> 桌面端 agent，工作区、会话、工具与多代理

`AI 编程助手` · 建议 12 分钟 · 基础

## 学完这一节，你会

- 理解 dsh 的工作区与会话模型
- 知道它能调用哪些工具
- 会用权限与沙箱控制风险

## 它是什么

dsh（DeepSeek Harness）是一个**桌面端 agent 应用**，不是命令行工具。打开后是一个本地界面：左边选工作区与会话，右边对话，agent 在后台调用文件、终端、搜索等工具。当前版本没有独立的 `dsh` 命令行入口，网上如果看到「dsh xxx 命令」多半是别的工具，别照搬。

## 界面里的几个概念

| 概念 | 含义 |
| --- | --- |
| 工作区 | 一个项目目录，agent 默认只能在这里读写 |
| 会话 | 一段连续对话，有自己的上下文和历史 |
| 预设 | 一套 agent 配置：模型、工具、提示词 |
| 权限策略 | 哪些操作需要你确认，哪些直接执行 |
| 沙箱模式 | 允许改的范围：仅工作区，或整台机器 |

## 它能调用的工具

和终端类 agent 类似，但工具是内置的：读文件、写文件、精确编辑、按模式找文件、按内容搜索、执行命令、抓取网页，以及**运行一段 TypeScript 程序**来编排多个工具调用。

## 常用工具与边界

| 工具 | 做什么 | 注意 |
| --- | --- | --- |
| 读 / 写 / 编辑 | 查看与修改文件 | 写入前先读，避免覆盖 |
| 搜索 | 按文件名或内容定位 | 大仓库先缩小目录 |
| 终端 | 执行命令、跑测试 | 危险命令会请求确认 |
| 代码执行 | 用脚本批量调用工具 | 适合重复性检查与统计 |
| 子代理 | 把独立子任务分出去并行做 | 适合调研、审查、批量修改 |

## 权限与沙箱

dsh 把「要不要问你」和「能改哪里」分成两层：**审批策略**决定哪些操作需要确认，**沙箱**决定文件系统范围。`workspace-write` 只能改当前工作区；`danger-full-access` 可以碰整台机器。日常开发保持工作区写入即可。只有确实需要装系统包、改全局配置时，才临时放宽。

## 一次典型任务

### 1. 选对工作区

一个工作区对应一个项目。开错目录，agent 会对着错误代码库工作。

### 2. 新建会话

一个任务一个会话。长会话上下文会变脏，切换任务时新开更干净。

### 3. 先读后写

让它先说明要改哪些文件、为什么，再批准动手。

### 4. 验收

看 diff、跑测试；不满意就指出具体位置，而不是让它「再改改」。

## 多代理与技能

dsh 支持把任务拆给**子代理**并行处理，也支持**技能包**（成组的操作说明与脚本）。做大型重构或调研时，可以让子代理分别读不同模块，最后汇总。技能适合把「每次都一样的流程」固化下来。

> **提示：把工作区当边界**
>
> 不要把家目录设为工作区。工作区越精确，误改的范围越小，agent 搜索也越快。

> **注意：别把「全权限」当默认**
>
> 全权限模式适合一次性、可丢弃的环境。日常项目里开着它，一次误操作就可能改到系统配置或别的仓库。

## 一段可以直接用的任务描述

```text
目标：给设置页加上「导出配置」按钮，导出当前设置为 JSON。
范围：只改 src/pages/settings 与 src/lib/export.ts，不要动路由。
验收：点击后下载 settings.json，内容包含主题与语言两项；补一个单测。
```

> `工作区、范围、验收都写清楚，子代理并行时也不会改到同一批文件。`

## 附件与长任务

`需要它看截图、日志或设计稿时，把文件作为附件放进会话，比口头描述准确。长任务分阶段推进：先方案、再实现、最后验收，每阶段结束让它复述当前状态，避免上下文漂移。`

## 动手练一练

在 dsh 里完成一次「读 → 计划 → 改 → 验收」的小任务。

1. 新建一个只包含测试项目的工作区
2. 让 agent 先读结构并给出改动计划
3. 批准后完成一个小改动
4. 检查 diff 并运行测试

**完成标准**：整个过程没有越出工作区，改动可回滚。

## 小测验

<details>
<summary>展开题目与答案（3 题）</summary>

**1. dsh 的工作区是什么？**

- A. 一个聊天窗口
- B. agent 默认能读写的项目目录
- C. 模型列表
- D. 插件市场

<details><summary>答案</summary>

**B**。工作区划定文件边界：workspace-write 模式下，agent 只能在这里读写。

</details>

**2. workspace-write 与 danger-full-access 的区别是？**

- A. 模型不同
- B. 前者只能改工作区，后者可访问整台机器
- C. 速度不同
- D. 前者不能执行命令

<details><summary>答案</summary>

**B**。这是沙箱范围的两档：日常用工作区写入，装系统包等场景才临时放宽。

</details>

**3. 切换到一个新任务时，比较好的习惯是？**

- A. 继续用旧会话
- B. 新开一个会话
- C. 清空工作区
- D. 换模型

<details><summary>答案</summary>

**B**。旧会话的上下文会干扰新任务，新开会话更干净，也更容易回看。

</details>

</details>
