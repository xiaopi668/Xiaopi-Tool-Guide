# 什么是 AI 编程助手

> 补全、聊天、agent 是三件事，先分清再上手

`AI 编程助手` · 建议 10 分钟 · 入门

## 学完这一节，你会

- 分清补全、聊天和 agent 的区别
- 理解 agent 的「读-改-跑-看」循环
- 知道它在哪里会出错、需要你做什么

## 它不是更聪明的补全

很多人第一次用 AI 写代码，是在编辑器里让补全帮忙写下一行。那类工具只做一件事：根据上下文猜你接下来要敲什么，猜完就交给你。**agent** 是另一回事：它有自己的循环，能主动读文件、改代码、执行命令、读取输出，然后根据结果决定下一步。你给它一个目标，它自己拆步骤，中途不需要你一直盯着。

## 三种形态

| 形态 | 输入 | 能做什么 | 适合 |
| --- | --- | --- | --- |
| 补全 | 光标附近的代码 | 续写几行 | 重复性代码、样板 |
| 聊天 | 一段提问 | 解释、给建议、写片段 | 问概念、查报错 |
| agent | 一个目标 + 仓库 | 读文件、改文件、跑命令、看结果、再改 | 多文件改动、调试、迁移 |

## agent 的一轮循环

### 1. 读

搜索仓库、打开相关文件，先建立上下文。这一步做得越充分，后面越少返工。

### 2. 想

拆解任务，决定改哪几个文件、跑哪条命令。

### 3. 改

写代码或执行命令。多数工具在这一步会请求你批准。

### 4. 看

读取命令输出、测试结果、报错，再决定继续、修正还是停下问你。

## 能力边界

agent 很强，但它**看不到你没给它的东西**：没打开的文件、没说的约束、线上的真实状态。它也会**非常自信地做错**——写出一段能跑但逻辑不对的代码，或者引用了不存在的接口。所以你的角色不是「等它写完」，而是**给上下文、定验收标准、审 diff**。

## 两种常见误解

| 误解 | 实际 |
| --- | --- |
| 一句话就能得到能上线的功能 | 目标越具体，产出越可用 |
| 它改完就不用看了 | diff 和测试必须自己过一遍 |
| 越自动越好，权限全开 | 权限按需放宽，默认最小 |

> 把它当成一个**很快、但完全不了解你项目的新同事**：能力不差，需要交代清楚，也需要 review。

> **提示：先让它读，别急着写**
>
> 第一次进入一个仓库，最值钱的一句话是「先读一遍项目结构，告诉我它是怎么组织的，暂时不要改任何文件」。这句话能省掉后面大量「改错文件」的返工。

> **注意：它能执行命令，这既是能力也是风险**
>
> 能跑 `npm test` 的工具，同样能跑 `rm -rf`。所以主流 agent 都带权限确认和沙箱。**不要为了少点几次「允许」就把限制全关掉**，尤其是在真实项目目录里。

## 常见产品

Claude Code、Codex CLI、dsh（DeepSeek Harness）、OpenCode、Cursor 等都属于这一类。它们的**思想几乎一样**：给目标、读上下文、改文件、跑命令、等你确认。学会一个，换到另一个主要只是记命令。

## 一条最小可用的任务描述

```text
目标：首页在 4G 网络下首屏超过 3 秒，找出最慢的三个请求，先不要改代码。
约束：只读 src/ 与 public/，不要安装依赖，不要动构建配置。
验收：列出三个请求的耗时与原因，每条给出一个可验证的优化方向。
```

> `目标 + 约束 + 验收。加上这三行，agent 才知道什么时候该停。`

## 怎么判断一个工具是不是 agent

`看三件事：能不能**自己读多个文件**、能不能**执行命令并读取结果**、能不能**根据结果继续下一轮**。只有第一条是「问答 + 检索」，三条都有才是 agent。这也解释了为什么 agent 的教程里总在讲权限：它真的会动手。`

## 动手练一练

找一个你自己的仓库，让任意一个 agent 只读不改地介绍它，观察它先看哪些文件。

1. 打开 agent，进入项目目录
2. 输入：先读项目结构，说明入口、构建和测试怎么跑，不要修改文件
3. 对比它的描述和你自己的理解，看它漏了什么

**完成标准**：能说出它读了哪些文件、哪一步理解错了。

## 小测验

<details>
<summary>展开题目与答案（3 题）</summary>

**1. agent 和代码补全最本质的区别是什么？**

- A. 模型更大
- B. 它能自己执行命令并根据结果继续
- C. 它支持更多语言
- D. 它不需要联网

<details><summary>答案</summary>

**B**。补全只根据上下文续写；agent 有循环，能读文件、改代码、跑命令、看输出，再决定下一步。

</details>

**2. 第一次进入一个陌生仓库，最该让 agent 先做什么？**

- A. 直接重构
- B. 先读结构并解释，暂不改动
- C. 先跑测试
- D. 先提交一次

<details><summary>答案</summary>

**B**。先建立上下文再动手，能显著减少改错文件、误解架构造成的返工。

</details>

**3. 关于 agent 的输出，哪种态度是对的？**

- A. 能跑就是对的
- B. 它比我懂，直接合并
- C. diff 和测试都要自己过一遍
- D. 只要它说完成了就完成了

<details><summary>答案</summary>

**C**。agent 会自信地写出逻辑错误或不存在的接口。diff 与测试是最后一道防线。

</details>

</details>
