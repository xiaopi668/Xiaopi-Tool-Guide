# 终端效率：别名、历史与补全

> 把每天敲的命令压成几个字符，重复的动作交给 shell

`效率与排错` · 建议 12 分钟 · 基础

## 学完这一节，你会

- 把常用命令写成 alias 与函数放进配置文件
- 用 history 与 Ctrl+R 找回几天前那条命令
- 用 !$、cd -、目录栈少打一半字
- 知道哪些别名和写法会给自己挖坑

## 这一课只讲提速

前面的终端课已经讲过怎么移动目录、怎么看文件。这一课不重复那些基础命令，只回答一个问题：**同一件事，怎么少敲一半键。**

提速分三层：不敲（从历史里找回）、少敲（别名、函数、补全）、一次敲完（命令组合、花括号展开）。三层都依赖同一件事——你的 shell 有一个配置文件，每次启动会自动加载它。

macOS 默认 zsh（Z shell），配置文件是 `~/.zshrc`；多数 Linux 服务器默认 bash（Bourne Again Shell），配置文件是 `~/.bashrc`。先确认自己在哪个里：`echo $SHELL`。输出 `/bin/zsh` 就改前者，输出 `/bin/bash` 就改后者，改错文件不会报错，只是永远不生效。

## 别名：给长命令起个短名字

别名（alias）就是给一条命令起短名。用 `alias 名字=命令` 定义，用 `unalias 名字` 撤销。三条规则要记住：等号两边**不能有空格**；右边的命令里带空格就必须用单引号包住；别名只对当前这个交互式 shell 生效，关掉窗口就没了。

所以真正有用的别名必须写进配置文件。写完后用 `source ~/.zshrc` 让当前窗口重读一遍，之后新开的窗口会自动加载。想验证某个别名生没生效，直接敲 `alias ll`，有输出就是有。

## 把别名和函数写进 ~/.zshrc

```bash
# ~/.zshrc —— 用 bash 的话把同样的内容写进 ~/.bashrc

# 常用别名：短名 = 长命令
alias ll='ls -lh'          # 长格式，大小带单位
alias la='ls -lAh'         # 连隐藏文件一起列
alias gs='git status -sb'  # 一行一个文件
alias gd='git diff'
alias ..='cd ..'
alias ports='lsof -nP -iTCP -sTCP:LISTEN'   # 谁在监听端口
alias myip='curl -s ifconfig.me; echo'      # 查公网 IP

# 别名带不了参数，需要参数就写函数
mkcd() { mkdir -p "$1" && cd "$1"; }        # mkcd 目录名：建了再进
glog() { git log --oneline --graph --decorate -n 20; }

```

> 函数里的 "$1" 是第一个参数。写完先 source ~/.zshrc，再敲 mkcd demo 验证：目录建出来了，而且人已经在里面。

## 历史：你已经敲过一遍了

shell 把敲过的命令记进历史文件（zsh 是 `~/.zsh_history`，bash 是 `~/.bash_history`），`history` 打印出来，前面的数字是编号。

配合叹号就是历史展开（history expansion）：`!!` 上一条整条命令，`!$` 上一条的最后一个参数，`!*` 上一条的全部参数，`!128` 第 128 条，`!git` 最近一条以 git 开头的命令。后面加 `:p` 只打印不执行，比如 `sudo !!:p` 先看清楚再决定按不按回车。

## 叹号展开实际长什么样

```bash
$ history 3
$ npm install -g pnpm
$ sudo !!
$ mkdir -p ~/work/notes-2026
$ cd !$
$ pwd
  498  git status
  499  npm run build
  500  history 3
npm ERR! code EACCES
npm ERR! syscall mkdir
npm ERR! path /usr/local/lib/node_modules/pnpm
sudo npm install -g pnpm
mkdir -p /Users/you/work/notes-2026
cd /Users/you/work/notes-2026
/Users/you/work/notes-2026
```

> 这个例子里的 sudo !! 只是演示展开，不是推荐做法：用 sudo 装全局包会在系统目录留下 root 拥有的文件，以后每次升级都要 sudo。!! 会把上一条原样再执行一次，前面是 rm -rf 之类就没有第二次机会，所以先 !!:p。

## Tab 补全：顺带验证东西存在

补全（completion）不只是省字，它替你**验证**：敲 `cd ~/proj` 再按 Tab，补不出来就说明前缀不对或目录不在；补出来了再回车，就不会有「路径打错」这类错误。命令名、分支名、npm 脚本名同样能补。

zsh 首次使用要跑一遍 `compinit`，之后选项和子命令也能补；bash 需要装 `bash-completion` 包。`cd` 之后只按 Tab 会列出当前目录下所有子目录，这是找一个记不清名字的项目目录最快的方式。装 fzf 之后 Ctrl+R 会变成全屏模糊搜索。

## 值得抄进配置文件的几行

```bash
# ~/.zshrc
HISTSIZE=50000
SAVEHIST=50000
HISTFILE=~/.zsh_history
setopt HIST_IGNORE_DUPS    # 连续重复的命令只记一次
setopt HIST_IGNORE_SPACE   # 以空格开头的命令不进历史，临时命令用
setopt SHARE_HISTORY       # 多个窗口共用同一份历史
setopt HIST_VERIFY         # !! 先展开给你看，回车才执行
setopt AUTO_CD             # 直接敲目录名就进去，不用打 cd

autoload -Uz compinit && compinit
zstyle ':completion:*' matcher-list 'm:{a-zA-Z}={A-Za-z}'   # 补全忽略大小写

```

> HIST_VERIFY 是这里最值钱的一行：它把 !! 从「直接执行」改成「先给你看」，手感几乎不变，风险小很多。用 bash 的话，对应的是 HISTCONTROL=ignoreboth 和 shopt -s histappend。

## 命令组合：一次敲完三件事

三个连接符决定下一条什么时候跑：`;` 不管前面成功失败都跑；`&amp;&amp;` 前面成功（退出码 0）才跑；`||` 前面失败才跑。竖线 `|` 把上一条的输出交给下一条当输入。

几个每天都在用的组合：`mkdir -p app/{src,test,docs}` 一次建三个目录，花括号展开是 shell 自己做的，不依赖任何工具；`npm run build 2&gt;&amp;1 | tee build.log` 既在屏幕上看到又存成文件；`history | grep docker | tail -5` 翻出最近用过的 docker 命令；`cd /tmp || echo 目录不存在` 让失败有一句人话。

## 两个目录之间来回：cd - 与目录栈

`cd -` 回到上一个目录，并把目标路径打印出来。代码目录和日志目录之间来回，一天能用几十次，比重新敲一遍长路径快得多。

要在三四个目录之间跳，用目录栈（directory stack）：`pushd /var/log` 进目录并把原位置压进栈，`popd` 弹回上一层，`dirs -v` 看带编号的整个栈，`pushd +1` 直接跳到第 1 层。zsh 里加上 `setopt AUTO_PUSHD` 之后，普通的 `cd` 也会自动压栈，回退用 `cd -` 或 `popd` 都行。注意 `cd -` 只记一个「上一个」，跳三个目录就不够用了。

> **提示：先跑通，再起名**
>
> 别名最容易写坏的地方是**把还没跑通的命令包起来**。先在终端里完整敲一遍，确认输出对、报错清楚，再粘进配置文件改成别名。否则你以后每次出错，都要多怀疑一层「是不是我的别名写错了」。
>
> 起名也要避开已有命令：把 `ls` 设成 `ls -lh` 还凑合，把 `grep`、`cd`、`git` 改掉就不行——脚本和肌肉记忆都会跟着变，报错时你还以为自己用的是原版。真要包一层，用函数并且起个新名字。

> **注意：别名不生效的三个原因**
>
> **改完不生效**：你在 zsh 里改了 `~/.bashrc`。用 `echo $SHELL` 确认，别靠记忆。
>
> **当前窗口生效、新窗口不生效**：只敲了 `source` 没写进文件，或者写进了 `~/.zsh_profile` 这类不存在的文件。
>
> **只有脚本里不生效**：非交互式 shell 不展开别名，这是设计如此，不是配置错了。脚本里要用短名字，就写函数，或者把命令写全。另外 macOS 上从图标启动的图形程序读不到 `~/.zshrc`，编辑器终端里找不到 nvm 装的 node，通常就是这件事。

## 动手练一练

打开你自己的终端，先确认 shell 类型，再写三条每天都用得到的别名，最后用历史展开跑一条长命令。

1. 打印当前使用的 shell，确认该改哪个配置文件 —— `echo $SHELL`
2. 在配置文件末尾加三条别名（ll、gs、ports），保存后重新加载 —— `source ~/.zshrc`
3. 验证别名真的生效了 —— `alias ll`
4. 敲一条带长路径的命令，再用 !$ 复用它的最后一个参数 —— `mkdir -p ~/work/demo && cd !$`

**完成标准**：新开一个终端窗口，三个别名不用重新定义就能用，说明配置写对了。

## 小测验

<details>
<summary>展开题目与答案（3 题）</summary>

**1. 你在 zsh 里加了 alias，当前窗口却没生效，先去查哪件事？**

- A. 配置文件是不是写在了 ~/.bashrc
- B. 有没有执行 source ~/.zshrc
- C. zsh 是否支持 alias
- D. 是不是得重启电脑

<details><summary>答案</summary>

**B**。定义写在文件里只对新启动的 shell 生效，当前窗口要用 source 让它重读一遍。写错文件也会造成同样的现象，但验证 source 只花一秒，是最该先做的检查。

</details>

**2. 上一条命令是 mkdir -p ~/work/report-v2，这时 cd !$ 会做什么？**

- A. 回到上一个目录
- B. 进入 ~/work/report-v2
- C. 打印上一条命令的完整内容
- D. 清空历史记录

<details><summary>答案</summary>

**B**。!$ 是历史展开里的最后一个参数，等价于 !!:$ 的简写。上一条的最后一个参数正好是那个路径，于是 cd 拿到的就是它，长路径不用再敲第二遍。

</details>

**3. npm run build && git push 里的 git push 什么时候执行？**

- A. 无论构建成功失败都执行
- B. 构建成功后才执行
- C. 构建失败后才执行
- D. 两条命令并行执行

<details><summary>答案</summary>

**B**。&& 表示前一条退出码为 0 才继续。分号才是无条件继续，|| 是失败才继续。部署脚本里这条区别决定你推上去的是能跑的代码，还是一堆半成品。

</details>

</details>
