# 开始之前

> 这一节不教具体命令，只讲三件事：需要准备什么、养成哪几个习惯、遇到报错怎么读。

## 你需要准备什么

### 一台能自己装软件的电脑

指南里的命令在 macOS、Linux、Windows 上都能用，少数命令有平台差异，文中会单独标出：

| 场景 | 建议 |
| --- | --- |
| macOS | 自带「终端」App，Shell 是 zsh，开箱即用 |
| Windows | 建议装 Windows Terminal + PowerShell 7；涉及 `ls`、`grep` 的内容优先用 Git Bash |
| Linux | 自带终端，Shell 通常是 bash 或 zsh |

### 四个工具

| 工具 | 用来做什么 | 检查是否已安装 |
| --- | --- | --- |
| Git | 版本控制 | `git --version` |
| VS Code | 写代码和改文件 | `code --version` |
| Node.js | 跑前端项目、装 npm 包 | `node -v` |
| Python | 跑脚本、建虚拟环境 | `python3 -V` |

版本号能打印出来就够了，不用追求最新版。装不上的时候，先看官方文档的安装页，不要从第三方站点下载安装包。

### 一个练习用的空目录

后面的练习会删文件、改配置、重置提交。请**不要**在存放重要资料的目录里做这些操作。建议：

```bash
mkdir -p ~/practice/tools && cd ~/practice/tools
```

## 三个习惯

### 1. 先看清楚，再动手

删除、重置、覆盖类操作之前，先跑一次「查看」的命令：

- 删文件前先 `ls` 确认路径
- `git reset` 前先 `git status`
- 改配置前先复制一份 `cp config config.bak`

多花的这五秒钟，能省掉一整天的返工。

### 2. 读完整的报错，从第一行读起

报错是工具在告诉你哪里不对，不是它在骂你。读法：

1. **先看最后一行**：通常是结论，例如 `command not found`、`Permission denied`
2. **再往上找第一处**：后面的错误经常是第一处引发的连锁反应
3. **注意路径和行号**：它们直接告诉你去哪里看

### 3. 最小复现

遇到问题时，把场景缩小到最小：新建一个空目录，只保留能复现问题的那几行命令。绝大多数「诡异问题」在最小复现里会自己暴露出来。

## 怎么搜索和提问

搜报错时，去掉自己项目特有的部分，只留通用关键词：

| 不要这样搜 | 这样搜 |
| --- | --- |
| 我的项目起不来 | `EADDRINUSE: address already in use :::3000` |
| npm 装不上东西 | `npm ERR! ERESOLVE unable to resolve dependency tree` |
| git 推不上去 | `git push rejected non-fast-forward` |

提问时给出四样东西：**你做了什么、期望是什么、实际发生了什么、完整报错**。这四样齐了，别人（和 AI）才帮得上忙。

## 怎么用这份指南

- **按顺序读**：从 [终端与系统](terminal/01-终端-Shell-与一条命令的解剖.md) 开始，29 节大约 6 到 8 小时
- **边读边做**：每节末尾的「动手练一练」请在真实终端里跑一遍
- **不懂就查**：[术语表](appendix/术语表.md) 和 [命令速查](appendix/命令速查.md) 可以随时翻
- **别背命令**：知道有这么个命令、用的时候查得到，就足够了
