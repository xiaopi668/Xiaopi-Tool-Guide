# 术语表

> 用大白话解释，不抄定义。看文档卡住时先回这里。

| 术语 | 英文 | 说明 |
| --- | --- | --- |
| 终端 | Terminal | 一个让你输入文字命令的窗口。它本身不干活，只负责把你的命令交给 Shell 执行，再把结果打回来。 |
| Shell | Shell | 真正解释并执行命令的程序，常见的有 zsh、bash、PowerShell。终端是窗口，Shell 是窗口里那个翻译官。 |
| 工作目录 | Working Directory | 你当前所处的文件夹。相对路径都从这里开始算，pwd 就是查看它。 |
| 路径 | PATH | 两件不同的事：文件路径是文件在磁盘上的位置；环境变量 PATH 是系统查找命令时的目录清单。 |
| 标准输出与标准错误 | stdout / stderr | 命令正常结果为 stdout，报错信息为 stderr。两者默认都打到屏幕，所以可以用 2> 单独接走错误。 |
| 退出码 | Exit Code | 每条命令结束后返回的数字，0 表示成功，非 0 表示失败。脚本靠它判断上一步有没有出错。 |
| 仓库 | Repository | Git 管理的项目目录。里面除了你的文件，还有一个隐藏的 .git 文件夹，存着全部历史。 |
| 工作区 | Working Tree | 你眼前能编辑的文件状态。改了还没 add，改动就只存在于工作区。 |
| 暂存区 | Staging Area | 准备进入下一次提交的改动清单。add 是往里放，commit 是把里面的内容定格成历史。 |
| 提交 | Commit | 一次带说明的快照，记录了那一刻全部文件的状态和它的父提交。历史就是由一串提交组成的。 |
| 分支 | Branch | 指向某条提交的可移动指针。新建分支不是复制整个项目，只是多了一个指针，所以非常便宜。 |
| HEAD | HEAD | 指向你当前所在分支或提交的指针。切换分支本质上就是移动 HEAD。 |
| 远程仓库 | Remote | 放在服务器上的仓库副本，比如 GitHub。push 是上传提交，pull 是下载并合并。 |
| 合并冲突 | Merge Conflict | 两条分支改了同一处内容，Git 不知道该听谁的，就把两边都标出来让你选。 |
| 变基 | Rebase | 把你的提交逐个搬到另一条分支的最新提交之后，历史会变成一条直线。别对已经推送的公共分支做。 |
| 环境变量 | Environment Variable | 操作系统传给程序的键值对配置，比如 PATH、HOME。程序启动时读取，修改后通常要新开终端才生效。 |
| 依赖 | Dependency | 你的项目运行所需要的别人的代码包。装在 node_modules 或虚拟环境里，不写进仓库。 |
| 包管理器 | Package Manager | 负责下载、安装、升级依赖的工具，比如 npm、pnpm、pip。它同时管理版本锁定文件。 |
| 虚拟环境 | Virtual Environment | 给一个 Python 项目单独准备的依赖目录，避免装到系统 Python 里互相打架。 |
| 容器 | Container | 把程序和它的运行环境一起打包的轻量隔离单元。换台机器也能用同样的方式跑起来。 |
| 镜像 | Image | 容器的只读模板。docker run 一个镜像，才会启动一个容器实例。 |
| SSH | Secure Shell | 加密的远程登录协议。用密钥代替密码，可以免密登录服务器，也是 Git 连接 GitHub 的方式之一。 |
| 公钥与私钥 | Public / Private Key | 一对配对的密钥。公钥可以随便发给别人，私钥必须只留在自己机器上，泄露等于把钥匙给了别人。 |
| 断点 | Breakpoint | 在代码某一行做的标记。调试器运行到那里会暂停，让你查看当时的变量和调用栈。 |
| 开发者工具 | DevTools | 浏览器内置的调试面板，能看页面结构、改样式、抓网络请求、打 JS 断点。前端排错的主战场。 |
| Lint | Linter | 静态检查工具，在运行前找出语法错误、可疑写法和风格问题，比如 ESLint。 |
| 构建 | Build | 把源码转换成能上线的产物，比如压缩、打包、转译。构建失败通常先看第一条错误。 |
| 端口 | Port | 一台机器上区分不同服务的数字编号。localhost:3000 的 3000 就是端口，被占用时服务起不来。 |
