# 安装与第一次配置

> 四条命令把 Git 配成能干活的工具

`Git 与版本控制` · 建议 12 分钟 · 入门

## 学完这一节，你会

- 确认本机装好了 Git 且版本够新
- 配好用户名邮箱，让提交有署名
- 能在新目录里 init 或 clone 仓库
- 把 SSH 公钥加到 GitHub 并验证

## 先确认你装的是哪个 Git

macOS 自带一个 Git，但它可能来自 Command Line Tools，版本偏旧；Windows 需要自己装 Git for Windows，官网是 git-scm.com，安装时记得勾选 Git Bash。

版本决定你能用哪些命令：`git switch` 和 `git restore` 需要 2.23 以上，配置项 `init.defaultBranch` 需要 2.28 以上。低于 2.23 只能继续用 `git checkout`。

装完先开一个新终端窗口，旧窗口里的 PATH 不会自动更新。

## 第一条命令

```bash
$ git --version
git version 2.43.0
```

> 看到版本号就说明装好了。如果提示 command not found（Windows 上是「不是内部或外部命令」），说明没装或没进 PATH，重装并在向导里选择把 Git 加入 PATH。

## 两条配置决定提交算谁的

Git 要在每条提交上写作者名字和邮箱。不配的话第一次 `git commit` 会直接拒绝，报 `Author identity unknown`，下面跟着一串提示让你去配 user.email 和 user.name。

邮箱尤其重要：GitHub 靠它把提交算到你账号头上。写错了照样能提交，只是网页上不显示你的头像，也不进贡献图。

加 `--global` 会写进用户目录的 `~/.gitconfig`，对这台机器所有仓库生效。公司项目要求用公司邮箱时，进那个仓库不带 --global 再跑一次，覆盖全局值。

## 三条命令，一次配好

```bash
$ git config --global user.name "Lin" && git config --global user.email "lin@example.com" && git config --global init.defaultBranch main
```

> 没有输出就是成功，Git 的配置命令默认很安静。第三条让以后 git init 出来的分支直接叫 main，不用再 git branch -m。名字和邮箱换成你自己的，别抄这一行。

## 看清楚每个值是谁给的

```bash
$ git config --list --show-origin
file:/home/lin/.gitconfig	user.name=Lin
file:/home/lin/.gitconfig	user.email=lin@example.com
file:/home/lin/.gitconfig	init.defaultbranch=main
file:/home/lin/blog/.git/config	core.repositoryformatversion=0
file:/home/lin/blog/.git/config	remote.origin.url=git@github.com:lin/blog.git
```

> 每行前面的 file: 告诉你这个值来自哪个文件。~/.gitconfig 是全局的，仓库里的 .git/config 只对这个项目生效，同名的写在后面的覆盖前面的。

## 值得一次配好的六项

| 配置项 | 常用值 | 作用 |
| --- | --- | --- |
| user.name | Lin | 提交记录里显示的作者名 |
| user.email | lin@example.com | GitHub 靠它把提交归到你账号 |
| init.defaultBranch | main | git init 时的默认分支名 |
| core.editor | code --wait | 写提交信息时打开哪个编辑器 |
| core.autocrlf | Windows 填 true，macOS 填 input | 统一换行符，避免整文件显示成改动 |
| pull.rebase | true | pull 时默认 rebase，少产生合并提交 |

> **注意：名字邮箱写错的两种后果**
>
> 一是用公司邮箱提交了个人项目，二是邮箱差一个字母，GitHub 上贡献图一片空白。已经写进历史的记录不会因为改配置而变。
>
> 只改最近一条提交，用 `git commit --amend --reset-author`；批量改历史要用 `git filter-repo`，那是重写哈希的操作，团队分支上必须先打招呼。
>
> 提交前别猜当前值：`git config user.email` 只输出这一项，`git config --show-origin user.email` 还会告诉你它来自哪个文件。

## init 与 clone：两个入口

`git init` 在**已有目录**里建一个 `.git` 文件夹，把现有文件变成可跟踪状态。它不改动任何文件内容，只多一个目录。

`git clone` 从远程地址复制整个仓库到本地新目录：全部历史、默认分支、一个叫 origin 的远程地址，还会自动把本地 main 设成跟踪 origin/main。

顺序别搞反：先 clone 再改代码。先下载 zip 再 init 会得到一个没有历史的新仓库，以后 pull 会报 unrelated histories，很难收拾。

## 克隆一个仓库

```bash
$ git clone git@github.com:lin/blog.git
Cloning into 'blog'...
remote: Enumerating objects: 128, done.
remote: Counting objects: 100% (128/128), done.
remote: Compressing objects: 100% (96/96), done.
Receiving objects: 100% (128/128), 42.10 KiB | 1.20 MiB/s, done.
Resolving deltas: 100% (60/60), done.
```

> 没报错就是成功，当前目录下会多出 blog 文件夹。想换本地目录名，在地址后面加一个名字，例如 git clone 地址 my-blog。

## 先把 .gitignore 写好，再开始提交

```text
node_modules/
dist/
.env
.env.*
!.env.example
.DS_Store
*.log
.idea/
.vscode/
```

> node_modules 和 dist 随时能重新生成，提进去只会让仓库膨胀。.env 里是密钥，推上去等于公开。叹号开头的行是例外，用来放行 .env.example 这种模板文件。

## 把 SSH 公钥加到 GitHub

### 1. 生成一对密钥

跑 `ssh-keygen -t ed25519 -C "lin@example.com"`。它先问保存路径，直接回车用默认的 `~/.ssh/id_ed25519`；再问两遍密码短语（passphrase），可以留空直接回车，也可以设一个更安全的。

-t ed25519 指定算法，比老 RSA 更短更快；-C 后面的注释只是方便你以后认出这把钥匙属于哪台机器。

### 2. 复制公钥内容

macOS 用 `cat ~/.ssh/id_ed25519.pub`，要的就是带 .pub 的那一行。Windows 在 PowerShell 里跑 `type $env:USERPROFILE\.ssh\id_ed25519.pub`，或者在 Git Bash 里用 cat。

带 .pub 的是公钥，可以随便给人；不带 .pub 的是私钥，一个字都别往外发。

### 3. 粘到 GitHub

打开 GitHub，右上角头像 → Settings → 左侧 SSH and GPG keys → New SSH key。Title 写这台机器，比如 macbook-2024；Key 粘贴刚才那一整行，保存。

### 4. 验证连接

跑 `ssh -T git@github.com`。第一次连接会问是否信任 github.com 的指纹，输 yes。看到 Hi 加你的用户名就通了。

## 验证结果长这样

```bash
$ ssh -T git@github.com
Hi lin! You have successfully authenticated, but GitHub does not provide shell access.
```

> 后半句是说 GitHub 不提供 shell，属正常现象。如果看到 Permission denied (publickey)，先用 ssh -vT git@github.com 看客户端拿了哪把钥匙，再回 GitHub 确认公钥粘贴完整、没有漏掉结尾的注释。

## 动手练一练

检查版本、配好身份、新建一个仓库并写 .gitignore，最后用一个本地测试连接验证 SSH 是否通。

1. 确认版本在 2.23 以上 —— `git --version`
2. 设置名字与邮箱，再用 --show-origin 看清来源 —— `git config --global user.name "你的名字" && git config --global user.email "you@example.com" && git config --show-origin user.email`
3. 新建仓库并把 .gitignore 一起提交 —— `mkdir setup-lab && cd setup-lab && git init && printf "node_modules/\n.env\n" > .gitignore && git add . && git commit -m "chore: 初始化项目"`
4. 测试 GitHub 连接，看到 Hi 加用户名即成功 —— `ssh -T git@github.com`

**完成标准**：git config --show-origin 能指出邮箱来自哪个文件，且 ssh 测试返回 Hi 加你的名字。

## 小测验

<details>
<summary>展开题目与答案（3 题）</summary>

**1. git config --global user.email 和 git config user.email 的区别是什么？**

- A. 前者写入 ~/.gitconfig 对所有仓库生效，后者只写当前仓库的 .git/config
- B. 前者需要管理员权限，后者普通权限即可
- C. 前者只影响 push，后者只影响 commit
- D. 两者作用完全相同，只是写法长短不同

<details><summary>答案</summary>

**A**。global 会写进用户目录的 .gitconfig，对这台机器上所有仓库生效；不带 global 则只写当前仓库的 .git/config，并且优先级更高，能覆盖全局值。

</details>

**2. 你只下载了项目 zip 解压后 git init，之后 pull 报 unrelated histories 的原因是什么？**

- A. Git 版本太旧，不支持远程仓库
- B. zip 里没有 .git 历史，这个仓库与远程没有任何共同祖先
- C. 远程仓库设置了私有权限
- D. 缺少 .gitignore 导致 Git 无法识别项目类型

<details><summary>答案</summary>

**B**。merge 需要共同祖先来判断改动。新初始化的仓库与远程是完全独立的两段历史，只能靠 clone 或允许无关历史合并。

</details>

**3. ssh-keygen -t ed25519 -C 里的 -C 是在做什么？**

- A. 指定加密强度，数值越大越安全
- B. 给公钥末尾加一段注释，方便识别这把钥匙属于谁或哪台机器
- C. 指定私钥的保存路径
- D. 强制覆盖已经存在的密钥文件

<details><summary>答案</summary>

**B**。注释只是附在公钥末尾的可读文本，参与不了任何加密运算。真正决定算法和强度的是 -t 以及可选的 -b。

</details>

</details>
