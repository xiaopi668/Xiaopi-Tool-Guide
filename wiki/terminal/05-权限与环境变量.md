# 权限与环境变量

> 读懂 ls -l 的九个位，把 chmod 777 和 sudo 用在正地方。

`终端与系统` · 建议 15 分钟 · 基础

## 学完这一节，你会

- 读懂 ls -l 开头的九个权限位
- 用 chmod 和 chown 改对权限
- 说清 sudo 能做什么、代价是什么
- 让环境变量写在正确的启动文件里

## ls -l 的第一列怎么读

`ls -l` 每行开头那十个字符是权限，不是乱码。第一个字符是类型：`-` 普通文件、`d` 目录、`l` 符号链接。后面九个三位一组：**属主**（user）、**属组**（group）、**其他人**（other）。

每组三个字母顺序固定：`r` 读、`w` 写、`x` 执行，没有权限就用 `-` 占位。目录上的 `x` 表示「能不能进去」：一个目录只有 r 没有 x，你连 cd 都进不去。

## 看一个真实文件

```bash
$ ls -l ~/Projects/prompt学校/assets/js/data-terminal.js
-rw-r--r--  1 xiaopi  staff  18452  3 14 10:02 data-terminal.js
```

> rw- 属主可读写，r-- 属组只读，r-- 其他人只读。第三列的 1 是硬链接数，18452 是字节数。

## 九个位与它们的数字

| 符号 | 含义 | 数字 |
| --- | --- | --- |
| rwx | 读、写、执行全有 | 7 |
| rw- | 读和写，不能执行 | 6 |
| r-x | 读和执行，不能改 | 5 |
| r-- | 只读 | 4 |
| --- | 什么都不能做 | 0 |
| r-xr-xr-x | 755，脚本和目录最常见 | 755 |
| rw-r--r-- | 644，普通文件的默认值 | 644 |

## chmod：加号写法与数字写法

两种都常用。**符号写法**：`chmod +x deploy.sh` 给所有人加执行位；`chmod u+w notes.md` 只给属主加写；`chmod go-w config` 去掉属组和其他人的写权限。

**数字写法**：三位八进制，分别对应属主、属组、其他人。`chmod 755 deploy.sh` 等于 rwxr-xr-x，`chmod 644 notes.md` 等于 rw-r--r--。加 `-R` 递归处理整个目录，别对家目录随手用。

改归属用 `chown`，格式是 用户:组：`sudo chown -R $USER 目录`，能把用 sudo 建出来的目录从 root 手里拿回来。

## 给脚本加执行位

```bash
$ touch hello.sh && chmod 755 hello.sh && ls -l hello.sh
-rwxr-xr-x  1 xiaopi  staff  0  3 14 10:05 hello.sh
```

> 权限 644 的脚本直接执行会报 Permission denied，加上执行位才跑得起来。

> **注意：chmod 777 和 sudo 都不是万能药**
>
> `chmod 777` 让任何用户都能改、能执行这个文件。放在网站目录里，等于把上传目录变成别人放后门的入口；放在配置文件上，等于谁改完你都要重启一次。它只压住了「权限报错」，没解决任何真正的问题。
>
> `sudo` 是以 root 身份执行一条命令，短时间内的后续命令不一定再问密码。危险在于 `sudo rm -rf` 能删系统文件，`sudo npm install -g` 会把包装成 root 所有，之后普通用户改不动，只能用 sudo 修，越修越乱。
>
> 先读报错：`Permission denied` 多数是路径写错或属主不对，`ls -l` 看一眼比直接 sudo 快。

## 环境变量是随进程走的一张表

环境变量（environment variable）是一组键值对，由父进程传给子进程。你在终端里 `export` 一个变量，之后从这个终端启动的所有程序都能读到它。

三个动作：`printenv` 列出全部，`echo $PATH` 看单个，`export API_KEY=abc` 临时设一个（关掉终端就没了）。要长期生效，写进 Shell 的启动文件。

## 看一眼 PATH 长什么样

```bash
$ echo $PATH | tr ":" "\n"
/usr/local/bin
/usr/bin
/bin
/usr/sbin
/usr/local/go/bin
```

> tr 把冒号换成换行，一行一个目录。Shell 找命令时从上往下找，第一个命中的胜出。

## PATH 里谁先谁后

| 位置 | 放的都是什么 | 注意 |
| --- | --- | --- |
| /usr/local/bin | Homebrew 和手动安装的工具 | 通常排在系统目录前面 |
| /usr/bin | 系统自带命令 | ls、grep、python3 都在这里 |
| /bin | 最基础的命令 | 多数是 /usr/bin 的软链接 |
| ~/.nvm/versions/node/v20/bin | nvm 当前选中的 Node | nvm use 会改这一段 |
| 当前目录 . | 默认不包含 | 把 . 加进 PATH 等于允许运行任何同名文件 |

## 为什么改了启动文件却没生效

启动文件只在**新开**一个 Shell 时读取。改完没反应，是因为当前这个 Shell 早就读过了。两个办法：`source ~/.zshrc` 让当前窗口重读，或者关掉窗口重开。

zsh 读 `~/.zshrc`，登录 Shell 还会读 `~/.zprofile`；bash 读 `~/.bashrc`，macOS 上的登录 bash 读 `~/.bash_profile`。写错文件是最常见的「明明配了却不生效」，先 `echo $SHELL` 确认自己是哪个 Shell，再决定写哪个文件。

> **提示：which、command -v 和 type 的分工**
>
> `which node` 告诉你实际执行的是哪个文件，但它本身是外部命令，遇到别名会看走眼。`command -v node` 更可靠，别名、函数、内置命令都能查到。
>
> `type -a node` 列出所有同名来源，按查找顺序排列。装了两个版本的全局包时，用它一眼看出谁在前面。

## sudo 之前先想三秒

| 习惯性做法 | 更稳的做法 |
| --- | --- |
| 一报错就 chmod 777 | 先 ls -l 看属主和权限，判断该改哪一位 |
| 全局包装不上就整条 sudo npm install | 用 nvm 装 Node，全局包不碰系统目录 |
| 改完变量忘了 source，以为没生效 | 改完 source 一次，或者重开窗口 |
| 把项目放 /usr/local 下再用 sudo 编辑 | 项目放家目录，谁建的谁改，不需要 sudo |

> sudo 只是临时借用 root，不会改变文件归属；用它创建的文件，之后你会一直需要它。

## 动手练一练

造一个脚本、给它加上执行位、设一个环境变量，最后把实验文件删掉，别在家目录里留垃圾。

1. 建脚本并确认当前权限 —— `touch ~/perm-demo.sh && ls -l ~/perm-demo.sh`
2. 改成 755，再对比一次 —— `chmod 755 ~/perm-demo.sh && ls -l ~/perm-demo.sh`
3. 设一个临时变量，用子进程读它 —— `export DEMO_KEY=abc && printenv DEMO_KEY`
4. 看清 PATH 的查找顺序 —— `echo $PATH | tr ":" "\n"`

**完成标准**：两次 ls -l 结果不同，printenv 打印出了 abc，说明你掌握了权限和变量。

## 小测验

<details>
<summary>展开题目与答案（3 题）</summary>

**1. ls -l 显示 -rw-r--r--，这个文件的权限数字是？**

- A. 755
- B. 644
- C. 600
- D. 777

<details><summary>答案</summary>

**B**。三位权限分别换成数字：rw- 是 6，r-- 是 4，再一个 r-- 还是 4，合起来就是 644。意思只有属主能写，属组和其他人只能读，谁都不能执行。

</details>

**2. 一个目录的权限是 r--，你能 cd 进去吗？**

- A. 能，有读权限就够
- B. 不能，进目录需要 x 位
- C. 能进去，但看不到文件名
- D. 取决于文件的属主是谁

<details><summary>答案</summary>

**B**。目录上的 r 只允许列出里面的名字，x 才是进入和访问路径的权限。缺 x 时 cd 会直接报 Permission denied，看起来像「明明有读权限」。

</details>

**3. 在 ~/.zshrc 里加了 export，当前终端却没反应，原因是？**

- A. 变量名写错了
- B. 启动文件只在启动 Shell 时读取，需要 source 或重开窗口
- C. zsh 根本不读 .zshrc
- D. 必须用 sudo 才会生效

<details><summary>答案</summary>

**B**。当前 Shell 早就读完配置文件并进入运行状态。source ~/.zshrc 让它当场重读，或者关掉窗口重开一个，新 Shell 才会执行这一行。

</details>

</details>
