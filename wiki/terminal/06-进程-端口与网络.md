# 进程、端口与网络

> 从 ps 到 curl，定位占着端口的进程并把它干净地送走。

`终端与系统` · 建议 15 分钟 · 进阶

## 学完这一节，你会

- 用 ps 和 top 找到目标进程
- 分清 kill 与 kill -9 的后果
- 查出某个端口被哪个进程占用
- 用 curl 判断服务到底活没活

## 进程就是正在跑的程序

你敲一次命令，系统就创建一个**进程**（process），分配一个 **PID**（进程号）。进程有父子关系：终端启动 Shell，Shell 启动你敲的命令；关掉 Shell 时，它的子进程会收到挂断信号。

排查「端口被占用」「CPU 跑满」永远是同一条路：先找到 PID，再确认它是什么，最后才决定要不要杀。跳过第一步直接重启机器，问题会原样回来。

## 先看有哪些进程

```bash
$ ps aux | head -n 5
USER    PID  %CPU %MEM      VSZ    RSS   TT  STAT STARTED      TIME COMMAND
root      1   0.1  0.1  4312832   9216   ??  Ss    3 14 08:00   0:12.31 /sbin/launchd
xiaopi  812   4.2  1.8  8271521 152384 s001  S     3 14 09:12   1:04.22 node server.js
xiaopi  903   0.0  0.0  4268001   2048 s001  R+    3 14 10:01   0:00.01 ps aux
```

> STAT 列：S 睡眠、R 运行中、R+ 表示在前台。COMMAND 列能看到启动时带了什么参数，这一步常被忽略。

## 六个命令各管一段

| 命令 | 回答什么问题 | 例子 |
| --- | --- | --- |
| ps aux | 有哪些进程，PID 是多少 | ps aux \| grep node |
| top / htop | 谁在吃 CPU 和内存 | top -o cpu |
| kill | 给指定 PID 发一个信号 | kill 812 |
| kill -9 | 强制干掉，不给清理机会 | kill -9 812 |
| lsof -i :3000 | 谁占着这个端口 | lsof -i :3000 |
| ss -ltnp | 系统里哪些端口在监听 | ss -ltnp \| grep 3000 |

## kill 与 kill -9 的差别

`kill` 不带参数发的是 `TERM`（信号 15），意思是「请结束」。进程可以捕获它，先把缓存写盘、关掉连接、删掉临时文件，再安静退出。

`kill -9` 发的是 `KILL`（信号 9），进程无法捕获、无法忽略，内核直接回收。所以顺序是：先 `kill PID`，等两三秒；还在再 `kill -9 PID`。数据库、构建工具这类有状态的进程被 -9 杀掉，可能出现锁文件残留、迁移只做了一半。

## 端口被占用时怎么定位

```bash
$ lsof -i :3000; kill 812
COMMAND  PID    USER   FD   TYPE  DEVICE SIZE/OFF NODE NAME
node    812  xiaopi   18u  IPv6 0x9a1c      0t0  TCP *:3000 (LISTEN)
```

> lsof 输出里就有 PID 812。确认这是你自己的 node、不是别的项目之后，再 kill。杀不掉才用 kill -9 812。

## ss -ltnp：不用猜端口

`ss -ltnp` 列出所有监听中的 TCP 端口：`-l` 只看 listen，`-t` 只看 TCP，`-n` 显示数字端口不做域名解析，`-p` 带进程名和 PID（需要权限）。

这是 Linux 的命令。macOS 上没有 `ss`，用 `lsof -nP -iTCP -sTCP:LISTEN` 代替。查具体端口：`ss -ltnp | grep 3000`，有输出说明被占了，没输出说明服务根本没起来。

## curl：看响应头，以及发一个 POST

```bash
$ curl -I http://127.0.0.1:3000/health
$ echo "--- POST ---"
$ curl -X POST -H "Content-Type: application/json" -d @body.json http://127.0.0.1:3000/api/login
HTTP/1.1 200 OK
Content-Type: application/json; charset=utf-8
Date: Thu, 14 Mar 2024 02:22:31 GMT

--- POST ---
{"ok":true,"token":"demo-token"}
```

> -I 只发 HEAD，只看响应头，判断服务活没活最快。第二条是 POST，-d @body.json 表示从文件读请求体；加 -v 能看到完整请求头与握手过程。

## EADDRINUSE 排错表

| 现象 | 先查什么 | 常见原因 |
| --- | --- | --- |
| Error: listen EADDRINUSE :::3000 | lsof -i :3000 找 PID | 上次的 node 没退干净，或另一个项目占了同一个端口 |
| curl 报 Could not connect | ss -ltnp 看端口在不在监听 | 服务没启动，或只监听 127.0.0.1 而你用局域网 IP 访问 |
| 浏览器能开，curl 127.0.0.1 不行 | 核对端口和协议 | 端口写错；服务只监听 IPv6；或者你该用 https |
| kill 之后端口还占着 | lsof 再查一次 | 有父进程自动重启，或端口还在 TIME_WAIT |

## 127.0.0.1、localhost 与 0.0.0.0

`127.0.0.1` 是本机回环地址（loopback），只有这台机器能访问。`localhost` 一般解析到它，但解析顺序可能先给 IPv6 的 `::1`，于是出现「服务只监听 IPv4，curl localhost 却连不上」的怪事。用 `127.0.0.1` 最确定。

服务里写 `0.0.0.0` 表示所有网卡都监听，别的机器才连得进来；写 `127.0.0.1` 就只有本机能连。手机调试连不上电脑，八成是这里写错了。

## ping 只能说明网络通不通

```bash
$ ping -c 4 127.0.0.1
PING 127.0.0.1 (127.0.0.1): 56 data bytes
64 bytes from 127.0.0.1: icmp_seq=0 ttl=64 time=0.042 ms
64 bytes from 127.0.0.1: icmp_seq=1 ttl=64 time=0.041 ms
--- 127.0.0.1 ping statistics ---
4 packets transmitted, 4 packets received, 0.0% packet loss
```

> macOS 用 -c 4 限定次数，Windows 用 ping -n 4。ping 通不代表端口通，ICMP 和 TCP 是两回事。

> **注意：kill -9 和随手改 hosts 的代价**
>
> `kill -9` 跳过所有清理逻辑。开发服务器被 -9 掉，端口可能停在 `TIME_WAIT` 几十秒，重启照样 EADDRINUSE；数据库被 -9 掉，可能留下锁文件，下次启动直接拒绝服务。
>
> 另一种常见破坏是往 `/etc/hosts` 里加一行 `127.0.0.1 api.example.com`，忘了删，几天后排查「线上接口怎么返回本地数据」才发现。改之前先 `cp /etc/hosts /etc/hosts.bak`。

## 端口被占用，按这个顺序查

### 1. 确认端口真的被占

`lsof -i :3000` 或 `ss -ltnp | grep 3000`，有输出就记下 PID。

### 2. 确认这个 PID 是什么

`ps -p 812 -o pid,command`，看清是不是你自己的进程、属于哪个项目。

### 3. 先正常结束它

`kill 812`，等两三秒，再查一次端口是否空出来。

### 4. 杀不掉再强制

`kill -9 812`，随后立刻重启服务，观察有没有数据损坏。

## 动手练一练

起一个本地服务、查出它占的端口、正常结束它，全程不重启机器，也不重启终端。

1. 启动一个临时静态服务器 —— `python3 -m http.server 8000`
2. 另开一个窗口，查出占用 8000 的 PID —— `lsof -i :8000`
3. 先确认服务活着 —— `curl -I http://127.0.0.1:8000/`
4. 把 lsof 拿到的 PID 填进 kill，正常结束它 —— `kill 12345`

**完成标准**：lsof 已经查不到 8000 端口，再用 curl 访问会报连不上，说明进程真的退出了。

## 小测验

<details>
<summary>展开题目与答案（3 题）</summary>

**1. ps aux 里有个 node 进程占满 CPU，想让它先保存数据再退出，应该？**

- A. kill -9 PID
- B. kill PID
- C. kill -1 PID
- D. 直接重启机器

<details><summary>答案</summary>

**B**。kill 默认发 TERM 信号，进程能捕获它，先把缓存写盘、关掉连接再退出。kill -9 是内核直接回收，进程没有机会做任何清理。

</details>

**2. 启动服务时报 Error: listen EADDRINUSE :::3000，第一步做什么？**

- A. 换个端口重新启动
- B. 用 lsof -i :3000 找出占用的 PID
- C. 重装 Node
- D. 执行 kill -9 1

<details><summary>答案</summary>

**B**。EADDRINUSE 表示端口已被监听。先查清是哪个进程占着、是不是自己上次没退干净，再决定结束它还是换端口，不要盲目重启。

</details>

**3. 服务监听 127.0.0.1:3000，同事用你的局域网 IP 访问会怎样？**

- A. 正常访问
- B. 连不上，因为只监听了回环地址
- C. 能连上但很慢
- D. 只能 ping 通，打不开页面

<details><summary>答案</summary>

**B**。127.0.0.1 只在回环网卡上监听，外部流量根本进不来。要让同事访问，服务必须监听 0.0.0.0，并用局域网 IP 而不是 localhost 去连。

</details>

</details>
