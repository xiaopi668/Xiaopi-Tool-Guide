# 看文件与在文件里找东西

> cat 看小文件、less 翻大文件、grep 进内容、find 找路径。

`终端与系统` · 建议 14 分钟 · 基础

## 学完这一节，你会

- 按文件大小选对查看命令
- 用 less 翻页、搜索、退出
- grep 在内容里定位，find 在路径里定位
- 分清通配符与正则的差别

## 先分清两个问题

「这个文件里写了什么」和「这个文件在哪」是两件事，用两套命令。看内容用 `cat`、`less`、`head`、`tail`、`grep`；找路径用 `find`，或者 `ls` 加通配符。

新手最常浪费的一步，是拿 `cat` 打印一个几百兆的日志，屏幕滚几分钟，还把终端缓冲区塞满。大文件一律用 `less`，它按需读取，开多大文件都只占一屏内存。

## 小文件、头尾与行数

```bash
$ wc -l access.log; head -n 2 access.log; tail -n 2 access.log
8421 access.log
127.0.0.1 - - [14/Mar/2024 09:01:02] "GET / HTTP/1.1" 200 1024
127.0.0.1 - - [14/Mar/2024 09:01:05] "GET /app.js HTTP/1.1" 200 2321
10.0.0.7 - - [14/Mar/2024 10:22:41] "POST /api/login HTTP/1.1" 401 87
10.0.0.7 - - [14/Mar/2024 10:22:44] "POST /api/login HTTP/1.1" 500 61
```

> wc -l 数行数，head 看开头确认格式，tail 看结尾。日志的最新一条永远在最下面。

## 五个看内容的命令

| 命令 | 用在哪 | 注意 |
| --- | --- | --- |
| cat | 几百行以内的小文件、拼接配置 | 大文件会刷屏，只能 ⌃C 才停 |
| less | 几十万行的日志、源码 | 按 q 退出，按键见下一节 |
| head -n 20 | 只看开头，确认格式对不对 | -n 后面跟行数，省略默认 10 |
| tail -n 50 | 看最新的日志 | 加 -f 会一直跟着文件增长 |
| wc -l | 数行数，判断文件规模 | 统计的是换行符个数，不是字符数 |

## 跟着日志跑

```bash
$ tail -f logs/app.log
[09:31:02] INFO  server listening on 3000
[09:31:44] WARN  slow query 812ms path=/api/orders
[09:32:01] ERROR connect ECONNREFUSED 127.0.0.1:5432
```

> 它不会自己退出，按 ⌃C（Windows 为 Ctrl+C）停。加 -n 200 可以先垫出最后两百行再开始跟。

## grep：进文件里找一行

`grep` 按行匹配，默认输出命中的整行。`-n` 带行号，`-i` 忽略大小写，`-r` 递归进子目录，`-l` 只列文件名，`-c` 只给条数。

`-r` 会一路扫进 `node_modules` 和 `.git`，几十万文件扫几分钟没结果。用 `--exclude-dir` 排除：`grep -rn "TODO" . --exclude-dir=node_modules --exclude-dir=.git`。macOS 自带的是 BSD grep，不一定认这个参数，需要时 `brew install grep`，然后改用 `ggrep`。

## 在项目里找一行代码

```bash
$ grep -rn "EADDRINUSE" src/ | head -n 3
src/server.js:14:  // 端口被占用时 Node 抛出 EADDRINUSE
src/server.js:88:  if (err.code === "EADDRINUSE") {
src/net/check.js:31:  throw new Error("EADDRINUSE: port busy");
```

> 文件名和行号在冒号前面，可以直接拿去编辑器跳转。结果常常很多，接 head 截断。

## grep 还是 find

| 用错的写法 | 正确的分工 |
| --- | --- |
| find . -name "EADDRINUSE" 想搜代码里的字符串，永远搜不到 | find . -name "*.log" -type f 找文件名和类型 |
| grep -r 遍历整个磁盘，只为找一个文件叫什么名字 | grep -rn "EADDRINUSE" src/ 找文件里的内容 |
| 用 grep 找 .log 文件的位置，再挨个 cat | grep -r 时限定目录，并排除 node_modules 与 .git |

> 一句话记法：find 只看名字和属性，grep 只看内容。

## find：按名字和类型找文件

`find` 第一个参数是起点目录，后面跟条件。三个最常用：`-name "*.log"` 按文件名（引号必须有，否则 Shell 会提前展开）、`-type f` 只要文件、`-type d` 只要目录。

两个能省时间的参数：`-maxdepth 2` 限制深度，避免扫穿整个家目录；`-mtime -1` 找一天内改过的文件。要对结果逐个执行命令，用 `-exec 命令 {} \;`，花括号是占位符。

## 找文件，并且只要文件

```bash
$ find . -maxdepth 3 -name "*.log" -type f
./logs/app.log
./logs/access.log
./tmp/test.log
```

> 不加 -type f，名字叫 .log 的目录也会被列出来；加 -maxdepth 能明显加快。

> **注意：通配符和正则不是一回事**
>
> `*` 和 `?` 是 Shell 的**通配符**（glob）：`*` 任意多个字符，`?` 恰好一个字符，只用于匹配文件名，而且由 Shell 先展开。
>
> `grep` 用的是**正则**（regular expression），`*` 表示前一个字符重复任意次，所以 `grep "*.log"` 找不到 .log 结尾的行。更麻烦的是：当前目录里真有 .log 文件时，Shell 先把 `*.log` 展开成一串文件名，grep 拿不到文件名参数，就地等标准输入，看起来像卡住。
>
> 正确写法是 `grep "\.log$"` 或 `grep -F ".log"`；通配符留给 `find -name`。

> **提示：找大文件与找最近改动**
>
> 磁盘满了先找大文件：`du -sh * | sort -h | tail -n 10`，从大到小看最后十行。`sort -h` 认得 K、M、G 单位，不加它排序会出错。
>
> 找今天改过的文件：`find . -type f -mtime -1`。排查「谁动了我的配置」时，这条比翻 Git 历史更快。

## 动手练一练

找一份真实日志（没有就自己造几行），做完四件事：数行、看尾部、搜报错、定位文件。

1. 数一下日志一共多少行 —— `wc -l logs/access.log`
2. 看最后 20 行，确认最新一条请求 —— `tail -n 20 logs/access.log`
3. 统计 500 错误出现几次 —— `grep -c " 500 " logs/access.log`
4. 列出目录下所有 .log 文件的路径 —— `find . -maxdepth 3 -name "*.log" -type f`

**完成标准**：四条命令都有输出，并且你能指出哪条用了通配符、哪条用了正则。

## 小测验

<details>
<summary>展开题目与答案（3 题）</summary>

**1. 要打开一个 2GB 的日志文件，最合适的命令是？**

- A. cat app.log
- B. less app.log
- C. head -n 200000 app.log
- D. vim app.log

<details><summary>答案</summary>

**B**。less 按需读取，只占一屏内存，还支持搜索和翻页，按 q 退出。cat 会把整份内容刷进终端，几秒钟就能把缓冲区打满。

</details>

**2. 要在 src 下所有文件里找字符串 EADDRINUSE 并显示行号，正确的是？**

- A. find src -name "EADDRINUSE"
- B. grep -rn "EADDRINUSE" src
- C. grep "EADDRINUSE" src
- D. grep -l "EADDRINUSE" src

<details><summary>答案</summary>

**B**。find 只按文件名和属性匹配，不读文件内容。grep 加 r 参数才递归进目录，加 n 才带行号；直接给它一个目录却不加 r，它会报错说这是个目录而不是文件。

</details>

**3. grep "*.log" 为什么找不到以 .log 结尾的行？**

- A. 缺少 -i 参数
- B. grep 用正则，星号表示前一字符重复，不是通配符
- C. 必须先 cd 到文件所在目录
- D. 只有 sudo 才有权限匹配

<details><summary>答案</summary>

**B**。Shell 的通配符和正则语法完全不同：在 grep 里，星号只修饰它前面那一个字符。要匹配扩展名，写 "\.log$"，或者用 grep -F 当纯字符串匹配。

</details>
