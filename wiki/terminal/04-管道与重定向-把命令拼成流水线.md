# 管道与重定向：把命令拼成流水线

> 三条命令接成一条，并且不再被 > 覆盖文件坑一次。

`终端与系统` · 建议 14 分钟 · 基础

## 学完这一节，你会

- 说清 stdin、stdout、stderr 三条流
- 用管道把两三条命令接起来
- 把 > 与 2>&1 的顺序写对
- 知道 > 会在写入前清空文件

## 三条看不见的通道

每个进程一启动就有三条流：**标准输入**（stdin，文件描述符 0）、**标准输出**（stdout，1）、**标准错误**（stderr，2）。正常结果走 stdout，报错走 stderr，键盘输入走 stdin。

关键在于 stdout 和 stderr 是两条独立通道，默认都连到屏幕，所以看着分不清。重定向只搬走其中一条——这就是「命令明明报错了，日志文件里却什么都没有」的唯一原因。

## 六个符号

| 符号 | 作用 | 例子 |
| --- | --- | --- |
| \| | 把左边 stdout 交给右边当 stdin | ls -la \| grep .js |
| > | 把 stdout 写进文件，先清空 | echo hi > a.txt |
| >> | 把 stdout 追加到文件末尾 | echo hi >> a.txt |
| 2> | 把 stderr 写进文件 | node app.js 2> err.log |
| 2>&1 | 把 stderr 并到 stdout 一起走 | node app.js > all.log 2>&1 |
| 小于号 | 把文件内容喂给 stdin | sort names.txt |

## 接一条最简单的管道

```bash
$ ls -la | grep "\.js$"
-rw-r--r--  1 xiaopi  staff  1832  3 14 09:40 app.js
-rw-r--r--  1 xiaopi  staff   412  3 14 09:41 config.js
```

> ls 的输出没有画到屏幕上，而是直接喂给了 grep；屏幕上只剩匹配的那两行。

## 重定向：把输出搬到别处

`>` 把 stdout 写进文件，文件不存在就新建；`>>` 追加到末尾。反方向的 `&lt;` 把文件内容喂给命令的 stdin：`sort &lt; names.txt` 等于让 sort 直接读这个名单，不用你亲手打开。

顺序很重要。`2>&1` 必须写在 `>` 之后。写成 `命令 2>&1 > out.log` 时，stderr 仍留在屏幕上：Shell 从左往右处理，先把 2 指向当前 stdout（也就是屏幕），再把 stdout 改成文件。顺序换了，结果就完全不同。

> **注意：大于号会先把文件清空，这是数据丢失第一名**
>
> 敲下 `echo "x" > app.js` 回车的那一瞬，`app.js` 原有内容已经没了，然后才写入这一个字节。它不是「加进去」，是「换掉」。这个文件如果没进 Git，基本就没了。
>
> 要追加用 `>>`。想先看看会写成什么样，用 `tee`：`echo x | tee app.js` 至少能看见内容。历史命令里 `>` 和 `>>` 只差一个字符，按 ↑ 调出来复用时最容易出事。

## 把报错单独收走

```bash
$ node app.js > out.log 2> err.log; echo "exit=$?"
exit=1
```

> 正常输出进 out.log，报错进 err.log。echo "exit=$?" 打印上一条命令的退出码：0 是成功，非 0 是失败。

## /dev/null：黑洞与分流

`/dev/null` 是一个丢掉一切写入的设备文件。命令太吵又不想看，就把输出扔进去：`npm install > /dev/null 2>&1`，stdout 和 stderr 一起静音。

只想丢报错、保留正常输出，写 `命令 2> /dev/null`。反过来只想看报错、不想被进度条刷屏，写 `命令 > /dev/null`。用哪条，先想清楚你要的是结果还是要错误。

## 数一数日志里有多少条 ERROR

```bash
$ cat logs/app.log | grep ERROR | wc -l
37
```

> 三步流水线：cat 读出全文，grep 只留含 ERROR 的行，wc -l 数行数。这条能跑通，说明管道你已经懂了。

## 三个每天都在用的组合

| 场景 | 命令 | 要点 |
| --- | --- | --- |
| 看谁在跑 node | ps aux \| grep node | grep 自己也会出现在结果里，看 PID 那列 |
| 统计错误行数 | cat app.log \| grep ERROR \| wc -l | grep -c ERROR app.log 一步就够，管道写法更好读 |
| 找大文件 | du -sh * \| sort -h \| tail -n 10 | sort -h 认 K、M、G，不加它排序是错的 |
| 实时看错误 | tail -f app.log \| grep ERROR | 管道有缓冲，输出可能延迟；需要即时可用 grep --line-buffered |

> **提示：tee：既存文件又看屏幕**
>
> `tee` 把 stdin 同时写进文件和屏幕：`npm run build 2>&1 | tee build.log`。排查构建失败时特别有用，报错还在屏幕上，同时已经落盘。
>
> 加 `-a` 是追加而不是覆盖。想留下上一次的日志：`命令 | tee -a build.log`。在 CI 里把整段输出存下来，回头对比两次失败差在哪，靠的就是它。

## 同一个文件，两种命运

| 会丢数据的写法 | 更稳的写法 |
| --- | --- |
| echo "PORT=3000" > .env 把原有配置整份替换 | 追加配置用 >>，或者先 cp .env .env.bak |
| 路径打错，大于号顺手建了个空文件 | 先写到临时文件，确认内容后再 mv 过去 |
| 用 > 追日志，每次只剩最后一段 | 日志用 >> 或 tee -a，永远不覆盖 |

> 记住「> 只管 stdout」，就不会在 2>&1 上犯迷糊。

## 管道只搬 stdout，退出码只认最后一条

管道里前一个命令失败，后面的照样执行。`curl -s 坏地址 | grep ok` 的退出码是 0，因为 grep 成功了，脚本会把一切当成正常。

要判断整条流水线，bash 里看 `PIPESTATUS` 数组，zsh 里看 `pipestatus`；更省事的办法是在脚本开头写 `set -euo pipefail`：出错即停、未定义变量报错、管道中任一环失败就算失败。

## 动手练一练

自己造一份小日志，用管道和重定向把它拆成「统计结果」和「错误清单」两个文件。

1. 造一份带两行 ERROR 的测试日志 —— `printf "INFO ok\nERROR db\nINFO ok\nERROR timeout\n" > demo.log`
2. 数出 ERROR 的条数 —— `cat demo.log | grep ERROR | wc -l`
3. 只把匹配行写进文件，stderr 直接丢掉 —— `grep ERROR demo.log > err.txt 2> /dev/null`
4. 追加一行，再确认旧内容没被清掉 —— `echo "ERROR last" >> err.txt && cat err.txt`

**完成标准**：err.txt 里一共有三行内容，说明追加成功，原来的两行没有被清空。

## 小测验

<details>
<summary>展开题目与答案（3 题）</summary>

**1. 命令 a | b 里，a 的报错信息会去哪？**

- A. 一起交给 b
- B. 仍然直接打到屏幕上
- C. 被自动丢弃
- D. 写进 b 的标准输入的第二份

<details><summary>答案</summary>

**B**。管道只接管 stdout。stderr 还是连着终端，所以右边收不到错误信息。要把两者一起接过去，必须在管道前先把 2>&1 写好。

</details>

**2. echo "hi" > note.txt 对一个已有内容的文件做了什么？**

- A. 在末尾追加一行
- B. 先清空再写入 hi
- C. 询问是否覆盖
- D. 备份原文件后写入

<details><summary>答案</summary>

**B**。大于号在写入前就把文件截断成空，原有的内容一个字都不剩。要追加必须用两个大于号，历史命令里用 ↑ 复用时最容易漏。

</details>

**3. 下面哪种写法能把 stdout 和 stderr 都写进 all.log？**

- A. node app.js 2>&1 > all.log
- B. node app.js > all.log 2>&1
- C. node app.js > all.log 2> all.log
- D. node app.js | all.log

<details><summary>答案</summary>

**B**。Shell 从左往右处理重定向：先把标准输出指向 all.log，再把标准错误并到标准输出上，两条流才都进文件。顺序写反，报错就仍留在屏幕上。

</details>
